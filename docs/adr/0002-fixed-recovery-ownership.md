# Fixed recovery ownership

Status: accepted

Issues #1 and #10 establish an accepted, hard-to-reverse boundary: fixed recovery input and rendering live outside Lua. Recovery retains the selected-path identity, uses an independent physical Fn takeover after exactly two continuous seconds for healthy workers, keeps the healthy worker hidden and alive, and does not restart failed workers automatically during a running session. On supervisor startup only, a saved source with no failure marker gets one attempt, followed by one embedded-default attempt if startup fails. A live worker failure records the selected path, so the next supervisor startup skips another attempt at that known-bad source and starts the embedded default once. Neither path changes the selected-path state. If that default fails too, recovery owns input and display. The physical-hold deadline is separate from the two-second Lua callback watchdog and the 500 ms graceful-stop deadline. The safety path cannot depend on Lua because the selected worker may be the thing that failed to load, start, render, or stay alive. See issues #1 and #10 for the requirements behind this decision.
